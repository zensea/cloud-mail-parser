# Mailparser 功能实施计划

日期：2026-11-10；分支：`feat/mailparser-core`。

## 目标与交付边界

复用现有 Vue 3 / Element Plus、Hono、Workers、D1、邮箱归属及认证链，分阶段建设邮件解析平台。本分支交付第一阶段的完整流程：为已有邮箱配置字段规则，预览样本，新邮件自动处理，查询结果，导出 CSV / JSON，通过 Webhook 可靠投递和手动恢复。

本阶段不包含 PDF / DOCX / XLSX 内容解析、OCR、通用 AI 提取、行业模板商城、第三方 OAuth 连接器、团队空间和订阅支付。这些能力按下述路线推进，不能将第一阶段交付描述为全量对齐 Mailparser。

## 第一阶段设计

### 1. 数据与生命周期

- 新增独立解析配置、解析任务、投递尝试表；不改变现有邮箱及邮件表语义。
- 一个用户可以为自己的每个邮箱建立一个解析配置；所有查询、保存、预览、重放和导出均验证用户及邮箱归属。
- 规则是有版本的 JSON：字段键、来源、必填、按序执行的过滤器。保存配置使用版本检查，防止并发编辑覆盖。
- 来源包括主题、正文、HTML 转文本、发件人、收件人。过滤器包括前后关键词截取、RE2 正则提取、字面替换、空白整理、大小写、默认值、数字及日期转换。
- 任务保留提交时的输入、规则版本及投递目标快照。初版快照存 D1，单份上限 128 KiB；超限明确记录失败，不静默截断。附件和完整 MIME 的归档安排在第二阶段。
- `(解析配置, 邮件, 规则版本)` 唯一，重复触发不会创建重复任务。同一版本重新解析复用该任务；新规则版本可以生成独立结果。
- 禁用配置会暂停自动创建及执行任务，重新启用后恢复；首次启用只自动处理配置建立后的邮件，历史邮件通过用户操作提交。

### 2. 可靠执行

- D1 保存待处理任务及投递状态，使用有期限的租约与随机令牌领取任务，过期可恢复，迟到的执行者不能覆盖新结果。
- 收信完成后同步登记解析任务，再通过 `waitUntil` 尝试立即处理；每分钟定时任务补偿漏登记和未完成任务。
- 对补偿扫描和每批执行设置上限，按扫描时间公平处理配置；复用已有每小时维护任务。
- 解析校验失败与外部投递失败分别展示。解析失败可修正规则后重新提交；投递使用有上限的指数退避，支持手动重试。
- Webhook 固定为 HTTPS POST JSON，提供稳定幂等键及可选认证头；禁止重定向，配置超时，限制地址和载荷长度，不记录认证秘密及响应正文。
- 网络超时可能意味着接收端已经执行，接收端需要按幂等键去重；不承诺跨系统恰好执行一次。
- 本阶段采用 D1 持久化队列以减少部署前置条件；高吞吐时再接入 Queues，继续保留任务状态与幂等约束。

### 3. API 与界面

- `GET /parser/accounts`：列出本人可配置的邮箱。
- `GET /parser/configs`、`POST /parser/configs`、`PUT /parser/configs/:id`：配置读取、创建和版本化更新；秘密不回显。
- `GET /parser/samples`、`POST /parser/preview`：读取本人样本、预览未保存规则及中间步骤。
- `POST /parser/enqueue`：提交本人历史邮件，或按当前版本重新解析。
- `GET /parser/jobs`、`GET /parser/jobs/:id`：分页查询状态、结果与投递尝试。
- `POST /parser/jobs/:id/retry`：显式重试解析或投递。
- `GET /parser/export`：按配置和游标分批导出 CSV / JSON；阻止 CSV 公式注入。
- 新增“邮件解析”导航，包含邮箱配置、字段及过滤器编辑、样本预览、结果和任务状态、重试、导出。复用现有主题、移动端布局及中英文语言切换。

### 4. 安全与兼容

- 所有新 API 经现有 JWT / KV 会话认证；对象查询始终包含 `user_id`，不依赖前端隐藏操作。
- 使用 RE2 兼容实现处理用户正则，不启用回溯和 lookbehind 扩展；限制字段数、过滤器数、正则长度及输入输出尺寸。
- 数据库迁移为幂等新增表和索引，接入现有初始化入口；旧邮件收发及旧全局 Webhook 保持原有行为。
- 不自动部署、调用远程数据库、发送真实邮件或向用户未配置的外部服务投递测试数据。

## 实施顺序与验收

1. **计划与分支**：确认干净基线，创建分支，记录范围及设计。
2. **规则引擎**：完成配置校验、提取、逐步预览、类型校验、导出；验证中文、多行、空值、不合法正则及资源限制。
3. **持久化与调度**：完成幂等迁移、归属检查、版本检查、任务快照、租约、自动补偿、投递记录及重试。
4. **API 与收信接入**：完成认证下的配置、样本、任务、导出；接入真实邮件处理函数和定时入口。
5. **界面**：完成规则配置、预览和结果操作；提供加载、失败、空状态、操作反馈与移动端布局。
6. **验证与文档**：使用本地 Workers / D1 验证迁移和 API、幂等、并发租约、断点恢复、跨用户拒绝、失败重试；构建前后端，验证浏览器流程；记录未完成的目标环境验证。

验收邮件示例：订单邮件中的订单号、客户邮箱、金额、日期能够按配置提取；相同事件重复触发只有一个任务；旧版本结果可追溯；投递故障可恢复；用户不能操作他人的配置和结果；导出文件可用且不会执行公式。

## 后续路线

### 第二阶段：多格式及附件

条件路由、HTML 表格及重复行、CSV / XLSX / DOCX / 文本 PDF、原始 MIME 归档、规则模板、批量重放、保留策略、Queues 执行。先收集代表样本，验证解析库、128 MB 运行时内存和 CPU，再决定重文档处理是否拆到独立服务。

### 第三阶段：产品化

AI 辅助生成并校验规则、行业模板、Google Sheets / CRM 等连接器、凭据生命周期、团队空间与细粒度权限、使用额度、订阅、审计及运行监控。每个连接器独立验收授权、限流、字段映射和重试。

## 部署、回退与成本

部署前先在备份后的目标数据库执行新增表迁移，再发布代码；配置定时触发器，验证一封脱敏样本。代码回退不删除新增表，已有邮件服务继续使用原有表。暂停功能时禁用解析配置。第一阶段增加 D1 快照、结果及轮询开销，暂不承诺免费套餐承载量，需根据实际样本、频率和任务积压测量。
