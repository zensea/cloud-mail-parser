# 邮件解析：使用、部署与验证

## 当前能力

本分支交付 [实施计划](mailparser-implementation-plan.md) 的第一阶段：每邮箱独立配置、主题和正文等字段提取、规则链及逐步预览、版本化结果、自动处理与补偿、CSV / JSON 分批导出、HTTPS Webhook 和失败恢复。

PDF / DOCX / XLSX 附件内容提取、OCR、AI 自动生成规则、第三方连接器、条件路由、团队空间及计量付费在后续阶段。已有附件收发、旧全局 Webhook 和邮件管理功能继续使用原有配置。

## 初始化与使用

1. 复用项目原有部署流程，绑定 D1 / KV，构建前端和 Worker。不要将测试配置 `wrangler-vitest.toml` 用于生产。
2. 升级前备份目标数据库；按项目原有 `/api/init/:secret` 初始化入口执行数据库升级。该入口会运行项目原有迁移，并幂等创建 `parser_config`、`parser_job`、`parser_delivery` 及其索引。调用使用自己的部署地址及管理员配置，不要把真实密钥写入脚本或提交到仓库。
3. 确认触发器包含 `* * * * *` 和原有的 `0 * * * *`。前者负责解析恢复，后者继续执行旧维护逻辑。开发配置没有自动启用定时器，可用 Wrangler 本地定时测试入口验证。
4. 登录后打开侧栏“邮件解析”，选择本人邮箱，编辑配置名称和字段。键名使用英文字母开头，可包含数字及下划线。
5. 用手动输入或本人历史邮件预览规则。预览不会保存配置、建立任务或向外发送数据；展开处理过程可以查看每一步的结果。
6. 保存并启用后，配置建立以后到达的邮件自动进入任务；较早邮件需选择后点击“处理选中邮件”。任务按提交时的规则和输入快照执行。修改规则并保存会创建新版本，同一邮件可产生不同版本的结果。
7. 在“处理结果”查看解析及推送状态；打开详情查看字段错误、规则版本及推送记录。可以重试失败任务。规则本身错误时应修改并保存配置，再重新提交邮件；仅重试旧任务仍使用旧规则。

## 规则与限制

- 来源：主题、纯文本正文、HTML 转文本、发件人地址、收件人地址。HTML 转文本会去除脚本、样式和标题元素。
- 步骤：前后关键词截取、RE2 正则提取、字面文字替换、首尾空白、合并空白、大小写、默认值、数字转换、日期标准化。
- 正则不含前后斜杠，捕获组 `0` 为完整匹配；支持 `i`、`m`、`s`。不支持反向引用和 lookbehind。正则不会交给原生回溯引擎执行。
- 日期输入格式必须明确选择，输出为 `YYYY-MM-DD`；不会猜测日/月顺序。
- 每配置最多 30 字段，每字段最多 12 步骤，规则 JSON 最多 32 KiB，正则最多 256 字符，输入快照最多 128 KiB，单字段输出最多 8192 字符。超限会明确失败，不截断成看似成功的数据。
- 暂停配置会暂停待处理解析和投递，重新启用后恢复。配置更改不会重定向旧任务的投递目标，详情展示任务建立时的目标地址。

## Webhook

填写公网域名的 HTTPS 地址，使用默认端口，不允许 URL 内用户名密码、IP 地址或重定向。可选认证信息原样放入 `Authorization` 请求头，保存后不会回显；留空保留，清除需勾选。

请求方式为 `POST`，`Content-Type` 为 `application/json`。示例：

```json
{
  "id": "parser-job-123",
  "emailId": 456,
  "parserId": 7,
  "version": 2,
  "data": { "order_id": "A-100", "amount": 128.5 }
}
```

相同事件带有稳定的 `Idempotency-Key: parser-job-123`。接收端必须持久化该键并去重：网络超时可能发生在接收端已经执行之后，因此无法承诺跨系统恰好执行一次。

请求超时为 10 秒，自动投递最多尝试 5 次，失败间隔依次为 1、2、4、8 分钟，并受每分钟调度影响。进程中断通过 60 秒租约恢复。耗尽后显示失败，可手动重新安排。日志只记录状态码及简要错误，不保存认证信息或响应正文。

## 导出与数据保留

导出仅包含成功解析的结果，每批最多 100 条。页面在还有数据时提供“继续导出”，每个 CSV 批次带独立表头；JSON 包含 `rows`、`nextCursor`、`hasMore`。接口 `/api/parser/export?parserId=...&format=json&cursor=...` 可用于认证后的持续取数。游标按完成时间和任务 ID 排序，能够纳入较晚完成的旧任务。

CSV 使用 UTF-8 BOM、引号转义及公式防护。JSON 保留字段类型；CSV 为文本表示。

第一阶段的任务、结果和输入快照独立于原邮件保存，因此原邮件定时清理不会中断已登记任务。永久删除用户或邮箱会通过数据库外键级联清除对应解析配置、任务及投递记录；软删除和禁用用户会暂停执行。尚未提供按时间自动清理解析历史的设置，应根据实际保留政策完成后续配置，并评估 D1 容量。当前没有高吞吐负载验收结论。

## 本地验证

后端 `npm test` 现在只运行本地 Vitest / Workers 测试；原来的测试环境部署脚本已改名为 `deploy:test`，只有明确准备部署时才调用。

```powershell
# mail-worker
npm install
npm test

# mail-vue：现有 Vite 7 / Vue 插件 peer 声明需要此安装选项
npm install --legacy-peer-deps
npm run build
```

本次验证包括：

- 43 项规则及本地 Workers / D1 测试：真实 MIME 收信（中文字符跨流分块）、现有 JWT / KV 认证、跨用户拒绝、重复提交、规则版本、输入快照、暂停、定时入口补偿、租约恢复、投递退避和重试、禁止重定向、导出游标、CSV 安全、资源限制及用户 / 邮箱删除级联。
- 隔离本地环境使用完整原有初始化流程、实际注册和登录；浏览器验证字段新增、来源选择、步骤调整、预览、保存及刷新、两版历史结果、详情、CSV / JSON 文件内容。
- 英文界面可加载，390 像素视口下文档宽度为 390，浏览器控制台无错误。已有无限滚动弃用提示仍存在。
- 前端生产构建成功，Worker `deploy --dry-run` 打包成功，没有发布到 Cloudflare。

现有 `@cloudflare/vitest-pool-workers` 的本地测试运行时会把兼容日期回退到 2025-03-10；另外使用当前 Wrangler 的本地运行时验证了项目配置的 2025-06-04 兼容日期。现有 Vite 环境变量及大块体积提示仍存在，未扩大范围处理。

尚未验证：目标 Cloudflare 账户实际套餐限制、真实外部 Webhook / 邮件投递、持续高并发和长期保留策略。异常投递测试使用本地受控响应，不向真实第三方发送测试邮件数据。

## 回退

暂停配置即可停止自动处理及待投递任务。回退代码时保留新增表，不删除原邮件表或邮箱数据。重新启用相同版本后，持久化任务可继续执行。迁移、代码发布和真实服务联调应在目标环境另行完成。
