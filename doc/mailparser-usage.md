# 邮件解析：使用、部署与验证

## 当前能力

本分支交付 [实施计划](mailparser-implementation-plan.md) 的第一阶段及第二阶段首批：每邮箱多套独立规则集、并发处理、解析匹配条件、字段提取、HTML 表格与 CSV 附件、规则链及逐步预览、版本化结果、自动处理与补偿、CSV / JSON 及表格明细分批导出、HTTPS Webhook、失败恢复和解析历史保留期限。

PDF / DOCX / XLSX 附件内容提取、OCR、AI 自动生成规则、第三方连接器、复杂嵌套条件、团队空间及计量付费在后续阶段。已有附件收发、旧全局 Webhook 和邮件管理功能继续使用原有配置。

## 初始化与使用

1. 由用户手工创建及绑定 D1 / KV、构建和部署前后端；本轮不操作 `main` 或部署工作流。继续使用 `feat/mailparser-core`。不要将测试配置 `wrangler-vitest.toml` 用于生产。
2. 升级前备份目标数据库；发布新版后，在使用解析功能前按项目原有 `/api/init/:secret` 初始化入口执行数据库升级。该入口会运行项目原有迁移，幂等创建解析表、下载链接表及索引，补充保留期限、匹配条件及扫描 / 调度时间字段，并移除旧的每邮箱单配置唯一约束。旧配置的编号、版本、任务、投递日志和自增编号保持不变。调用使用自己的部署地址及管理员配置，不要把真实密钥写入脚本或提交到仓库。
3. 确认触发器包含 `* * * * *` 和原有的 `0 * * * *`。前者负责解析恢复，后者继续执行旧维护逻辑。开发配置没有自动启用定时器，可用 Wrangler 本地定时测试入口验证。
4. 登录后打开侧栏“邮件解析”，选择本人邮箱，再选择规则集或点击“新增规则集”。填写规则集名称和字段；键名使用英文字母开头，可包含数字及下划线。
5. 用手动输入或本人历史邮件预览规则。预览不会保存配置、建立任务或向外发送数据；展开处理过程可以查看每一步的结果。
6. 保存并启用后，配置建立以后到达的邮件自动进入任务；较早邮件需选择后点击“处理选中邮件”。任务按提交时的规则和输入快照执行。修改规则并保存会创建新版本，同一邮件可产生不同版本的结果。
7. 在“处理结果”查看当前规则集的解析及推送状态；打开详情查看字段错误、规则版本及推送记录。可以重试失败任务。规则本身错误时应修改并保存配置，再重新提交邮件；仅重试旧任务仍使用旧规则。

## 同邮箱多套独立规则

同一邮箱可以新增多套规则集。每套分别保存名称、启用状态、匹配条件、提取字段、规则版本、Webhook 地址及凭据、历史保留期限和扫描进度。一封新邮件会分别检查所有启用的规则集，符合多套条件时全部建立独立任务，不以首套匹配为终点。重复触发仍按 `(规则集, 邮件, 版本)` 防重。

各套结果、投递幂等键、日志和导出相互独立。暂停、修改、重试或清理其中一套不会改变其他规则集；新增规则集只自动处理其建立之后的邮件，历史邮件可切换到该规则集后手动提交。页面会在切换时确认未保存改动，并隔离结果页、详情和导出游标；同一邮箱的历史样本可保留以便比较不同规则。

执行采用有界并发：每轮最多选择 10 套，最多同时执行 3 套；空出的执行位置立即处理后续规则集。一套内每轮最多解析 5 个任务、投递 2 个任务、补偿扫描 10 封邮件。扫描和处理按各自时间轮转；一套的慢 Webhook、校验失败或附件存储错误不会占用其他套的全部执行位置。收信会向每套分别登记，漏登记由每分钟调度按独立进度补偿。实际吞吐仍需结合目标套餐、数据库查询限制及任务量测量。

手动“处理选中邮件”和“重试”仅触发当前规则集；自动收信及定时调度处理所有符合条件的规则集。`GET /api/parser/configs?accountId=...` 可只读取当前邮箱，不传 `accountId` 仍兼容返回本人所有规则集。导出文件名包含规则集编号，内容仅属于选中的规则集。

### 旧数据库迁移

旧唯一约束由内联 `UNIQUE(user_id,account_id)` 创建，需要重建解析表。初始化在一个 D1 事务批次内备份三张解析表，按子表到父表顺序重建，再还原配置、任务、投递记录和自增计数；避免删除父表时触发历史数据级联清理。任一步失败会回滚整个重建，成功后重复初始化不会再次重建。[D1 批次事务说明](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)

请在维护窗口确保旧版本不再写入，先备份并预留解析数据副本所需空间，在目标环境执行初始化后再使用多规则功能。已有大量历史数据时，表复制的执行时间和空间尚未压测；失败后保留原数据并检查错误，不自动删除历史以腾出容量。

切换前验收失败可在停止新写入后恢复升级前备份及旧版本。开始使用多规则后，不应直接回退到单配置旧后端：它只读取一套配置，且旧新增语句依赖已移除的唯一约束。此时应保全新增数据并使用当前后端暂停额外规则集，再规划数据恢复；不通过删除其他规则集来强行恢复旧约束。

## 规则与限制

- 来源：主题、纯文本正文、HTML 转文本、发件人地址、收件人地址、HTML 表格、CSV 附件。HTML 会去除脚本、样式和标题元素，不加载外部内容。
- 步骤：前后关键词截取、RE2 正则提取、字面文字替换、首尾空白、合并空白、大小写、默认值、数字转换、日期标准化。
- 正则不含前后斜杠，捕获组 `0` 为完整匹配；支持 `i`、`m`、`s`。不支持反向引用和 lookbehind。正则不会交给原生回溯引擎执行。
- 日期输入格式必须明确选择，输出为 `YYYY-MM-DD`；不会猜测日/月顺序。
- 每配置最多 30 字段，每字段最多 12 步骤，规则 JSON 最多 32 KiB，正则最多 256 字符，输入快照及整体结果最多 128 KiB，文本字段输出最多 8192 字符。超限会明确失败，不截断成看似成功的数据。
- 暂停配置会暂停待处理解析和投递，重新启用后恢复。配置更改不会重定向旧任务的投递目标，详情展示任务建立时的目标地址。

## 解析匹配条件

“选择邮箱”已经限定解析范围，通常只需在“解析匹配条件”中配置发件人、主题或纯文本正文。最多 20 个条件，全部满足（AND）才建立解析任务；条件为空时所有邮件均可进入解析。匹配方式包括等于、不等于、包含、不包含、开头为、结尾为和 RE2 正则。默认不区分大小写，可逐条开启区分大小写。

“实际投递地址（含别名）”位于“高级条件”，普通邮箱通常无需设置。未单独创建别名邮箱时，`sales+orders@example.com`、`sales+news@example.com` 可归入基础邮箱 `sales@example.com`，此条件可限定只解析其中一种投递地址。高级区显示条件数量，已有投递地址条件会自动展开；折叠不会停用条件。原有 `source: "to"` 配置保持兼容，顺序和后端匹配行为不变。

发件人使用邮件 `From` 头中的地址，收件人使用实际投递邮箱（SMTP 信封收件人，与原邮件 `To` / `CC` 列表不同）；正文只比较纯文本内容。普通匹配值最多 512 字符，正则最多 256 字符，条件 JSON 最多 16 KiB，参与比较的单个来源最多 128 KiB。普通匹配按字面文字比较，正则复用 RE2 安全实现，不支持反向引用及 lookbehind。

例如：选择业务邮箱后，设置发件人等于 `orders@example.com`、主题包含“订单”，两项都满足才解析。不匹配的邮件正常保留，其他邮件收发功能保持原有行为；不建立跳过任务，也不读取附件或发送解析结果。输入超出匹配限制时明确记录任务失败，不会静默截断或当成未匹配。

预览使用当前编辑的条件，逐条显示通过或未通过；未匹配时不再提取字段。手动提交始终由后端使用已保存的条件检查，前端不能通过传入空条件绕过。接口兼容行为：

- 配置保存新增 `conditions` 数组；旧客户端更新时省略该属性会保留已有条件，显式传 `[]` 才清空。
- `/api/parser/preview` 返回 `match: { matched, checks }`，未匹配时 `data`、`fields` 为空，不表示字段验证失败。
- `/api/parser/enqueue` 未匹配时成功返回 `data: { matched: false, checks }`，没有任务 `id`；符合条件时保持原有任务返回结构。

保存条件会产生新配置版本，已登记任务仍使用原快照执行；重试旧任务不会重新检查新条件。补偿扫描使用持久化进度，每批最多检查 10 封邮件，未匹配邮件不会持续占据扫描首批。扫描遇到尚在保存的收信，或匹配邮件的附件暂不可读，会停在该位置等待恢复，避免越过未完成邮件。修改条件不会重置进度或自动重放已跳过邮件；如需处理这些历史邮件，请选择后手动提交。

## HTML 表格与 CSV 附件

字段来源选择“HTML 表格”时，填写表格序号（1–20，按 HTML 文档顺序，嵌套表格也计数）；外层表格提取时排除嵌套表格的行及文字。合并单元格暂不支持，避免列错位。选择“CSV 附件”时，填写完整文件名（区分大小写、包含 `.csv`），可从选中历史邮件的附件名中选择。没有匹配文件返回空数组，必填字段会报错；同名文件不猜测，明确报错。

CSV 支持逗号、分号、制表符，支持引号内分隔符、换行及双引号转义。仅支持 UTF-8（可含 BOM），每个文件最多 64 KiB，每封邮件最多选择 5 个附件；正文和附件合计仍受 128 KiB 快照限制。历史附件复用现有存储后端，未新增云资源；收信直接使用 MIME 已解码内容，任务持久化后不再依赖原附件存储。存储暂不可用返回可重试错误，不写入残缺快照。

可选“首行为列名”；无表头时列名为 `column_1`、`column_2` 等。空白或保留字表头使用自动列名，重复表头加后缀；表头最长 128 字符。每表最多 200 数据行、50 列，单元格最多 8192 字符，各行列数必须一致。表格结果为对象数组，可按步骤整理单元格空白、选择数据行范围（从 1 开始，两端包含）和选择精确列名；数值及日期单元格本阶段保留文本。

手动样本可输入 HTML，以及一个 CSV 文件名和内容；历史样本读取已授权邮件的实际附件。预览与任务详情均显示表格及 JSON，Webhook 使用同一对象数组结构。

## Webhook

填写公网域名的 HTTPS 地址，使用默认端口，不允许 URL 内用户名密码、IP 地址或重定向。可选认证信息原样放入 `Authorization` 请求头，保存后不会回显；留空保留，清除需勾选。

请求方式为 `POST`，`Content-Type` 为 `application/json`。示例：

```json
{
  "id": "parser-job-123",
  "emailId": 456,
  "parserId": 7,
  "version": 2,
  "data": { "order_id": "A-100", "amount": 128.5 }
}
```

相同事件带有稳定的 `Idempotency-Key: parser-job-123`。接收端必须持久化该键并去重：网络超时可能发生在接收端已经执行之后，因此无法承诺跨系统恰好执行一次。

请求超时为 10 秒，自动投递最多尝试 5 次，失败间隔依次为 1、2、4、8 分钟，并受每分钟调度影响。进程中断通过 60 秒租约恢复。耗尽后显示失败，可手动重新安排。日志只记录状态码及简要错误，不保存认证信息或响应正文。

## 导出与数据保留

下载仅包含成功解析的结果，默认最近 100 条、全部字段。页面一次生成完整文件，内部读取与合并批次；CSV 只包含一个表头。原接口 `/api/parser/export?parserId=...&format=json&cursor=...` 继续用于认证后的分批取数，保留按完成时间和任务 ID 排序的游标契约。

CSV 使用 UTF-8 BOM、引号转义及公式防护。默认按邮件导出，表格字段为 JSON 文本；选择“CSV 明细字段”后按选定表格逐行展开，列名为 `字段名.列名`，重复写入任务、邮件编号、版本和其他字段。空表没有明细行，不包含该表格字段的旧版本结果跳过。一次只展开一个表格，避免多个数组产生组合行；其他表格保持 JSON。JSON 下载不受明细选择影响。

每份完整文件最多 1000 条解析结果、4 MiB；超过限制会明确报错，需缩小结果范围或减少字段，不会返回截断文件。表格字段由当前保存规则列出，接口也可用 `tableField` 指定历史字段；JSON 保留字段类型。原分批导出接口保持每批最多 100 条、明细最多 10 条，可使用 `size` 缩小批次。

### 手动下载与固定下载链接

选择已保存的规则集，打开“下载”页签，选择 CSV / JSON 和结果范围后点击“下载”。默认下载最近 100 条成功结果及全部字段，也可选择最近 1 / 1000 条、今天、近 7 天、全部已保留结果或自定义时间。按解析完成时间及任务编号从新到旧排序，同一邮件不同规则版本的成功结果分别计数。“今天”按浏览器在保存配置时的 UTC 偏移计算；近 7 天为滚动 168 小时。固定链接每次访问时重新计算相对时间范围。

“高级设置”默认折叠，可切换为“指定字段”，选择字段或输入历史键名；选择自定义时间时自动展开日期输入。CSV 配置包含表格规则时才显示明细字段。已设置的高级条件在折叠后仍然生效，标题会提示已设置；批次数量、分页游标无需在页面配置。“处理结果”页的“下载结果”按钮直接进入此页面。

点击“创建固定链接”，在独立弹窗中填写名称，选择格式与范围后保存。创建默认仍为 CSV、最近 100 条、全部字段，不会继承刚才手动下载的临时选择。每套规则集最多 20 个链接，列表直接提供下载、复制、编辑和撤销，并保留重新生成入口。编辑改变设置并保持 URL 不变。固定链接为 `https://部署域名/api/parser-download/<令牌>`，无需登录、JWT 或全局公共密钥；任何持有者都能下载该链接范围内的成功结果。访问不触发邮件解析或 Webhook，也不删除结果。

令牌使用 256 位安全随机数，以 SHA-256 摘要验证公开访问，同时使用 AES-GCM 加密保存可恢复副本，密钥由部署的 `jwt_secret` 派生。只有经过原有会话和归属验证的管理接口才返回完整 URL，因此刷新后仍可复制。接口不返回摘要或加密内容，数据库不保存明文令牌。重新生成保留下载设置并立即使旧令牌失效；撤销删除该链接。已开始返回的响应不会被中断。下载响应禁止缓存并设置 `Referrer-Policy: no-referrer`。

新建页面生成的链接每次返回所选范围内的完整结果，不维护“自上次下载后”的共享进度。调用方不能通过规则集、字段、时间、格式、范围或游标参数扩大访问范围。公开 JSON 响应沿用 `{ code, message, data: { rows, hasMore, nextCursor } }`，完整文件的 `hasMore=false`；CSV 返回单个附件。两种格式都带附件文件名，JSON 下载到本地的文件保留 `rows` 等数据结构。

```javascript
// 示例 URL 中的令牌为占位符；使用自己创建的 JSON 下载链接。
const downloadUrl = 'https://your-domain.example/api/parser-download/REPLACE_WITH_TOKEN';
const response = await fetch(downloadUrl, { cache: 'no-store' });
if (!response.ok) throw new Error(`Download failed: HTTP ${response.status}`);
const { data } = await response.json();
console.log(data.rows); // 替换为自己的存储或处理逻辑
```

链接管理 API 为 `GET /api/parser/download-links?parserId=...`、`POST /api/parser/download-links`、`PUT /api/parser/download-links/:id`、`POST /api/parser/download-links/:id/rotate`、`DELETE /api/parser/download-links/:id`，均要求原有登录会话并验证归属。创建 / 完整更新参数包括 `parserId`、`name`、`format`、`range`，以及可选的 `fields` 数组、`fromTime` / `toTime`（含边界的毫秒时间戳）、`tableField`、`timezoneOffset`（浏览器 `getTimezoneOffset()` 值）。`range` 支持 `latest1`、`latest100`、`latest1000`、`today`、`last7days`、`all`、`custom`；自定义时间须包含起止时间。

认证后的完整下载接口为 `GET /api/parser/download?parserId=...&format=csv&range=latest100`，也可用 `downloadId` 按保存设置下载。原分批导出接口 `/api/parser/export` 保持兼容。升级初始化补充 `range_mode`、`timezone_offset` 和 `token_encrypted`；旧配置与未传 `range` 的旧创建请求仍使用 `legacy` 分批行为，公开链接继续接受 `cursor`。只有摘要的旧链接及更换 `jwt_secret` 后无法解密的链接仍可访问；再次复制时会提示明确重新生成，旧 URL 随后失效。应保留原密钥以避免不必要的重新生成。

暂停规则集会停止新增处理，仍可下载已保留的结果；禁用或删除用户、停用或软删除邮箱会拒绝免登录下载。解析历史清理后，链接不再返回已清理的内容；永久删除用户、邮箱或规则集会级联删除下载链接。新增 `parser_download` 表不修改已有下载或解析数据，重复初始化会保留已创建的链接；回退到不支持固定链接的代码后应同时停用这些 URL。

配置“解析历史保留天数”为 0–60，0 关闭；已有配置迁移默认 0，新建页面默认 30 天，保存后生效。到期以任务最后更新时间计算，每分钟最多清理 50 个已结束任务（解析失败，或已解析且无待发送 / 发送中投递）。清除输入、规则、结果、任务投递目标与凭据、错误和投递日志，状态变为“已过期清理”；只保留编号、版本、状态和时间等最小记录，避免补偿扫描重新解析和推送。相同版本不能重新提交已清理任务；保存新版本后可以显式重新提交。暂停配置仍会执行已设置的历史清理。配置自身的规则及凭据仍用于后续新邮件，不受任务历史清理影响。

原邮件及附件继续遵循原有保留策略，解析快照独立保存；清理解析历史不会删除原邮件。永久删除用户或邮箱会级联清除对应配置、所有任务和日志，软删除和禁用用户暂停执行。清理已发生的数据不能通过代码回退恢复，启用前确认保留期限。仍需评估 D1 容量，当前没有高吞吐负载验收结论。
